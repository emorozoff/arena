## 0. Контекст
Живое шоу: стартаперы по очереди питчат со сцены, судьи голосуют отдельно. Параллельно зрители в зале (около 100 человек) инвестируют в проекты виртуальные деньги со своих телефонов. Результаты выводятся на большой экран.

Работать всё должно **один вечер**, в зале с плохим интернетом, без права на ошибку. Приоритеты в такой последовательности: надёжность → простота управления со сцены → красота экрана → фичи.

Разработчик не умеет писать код и будет вести проект через Claude Code. Поэтому: минимум зависимостей, максимум понятных названий, никакой магии.

## 3. Вход зрителя
1. На экране в зале висит **один общий QR-код** со ссылкой на `/join`.
2. Зритель сканирует, попадает на страницу с одним полем: **номер билета**.
3. Вводит номер → нажимает «Войти» → попадает в `/app`.
4. Устройству выдаётся токен, он сохраняется в `localStorage` и в cookie. При повторном открытии ссылки зритель сразу попадает в `/app` без повторного ввода.

### Два режима проверки билетов (переключается в админке)
- **`whitelist`** - в базе есть список валидных номеров. Номера нет в списке → ошибка «Билет не найден».
- **`free`** - списка нет. Принимается любой номер, подходящий под формат (настраивается в админке: длина и допустимые символы). Первый, кто ввёл номер, становится его владельцем.

Режим `free` - это дефолт, потому что списка билетов может не быть. Код должен поддерживать оба без переписывания.

### Правила
- Один номер билета = один зритель = один бюджет.
- Если номер уже занят другим устройством → ошибка «Этот билет уже используется». Отдельная кнопка «Это мой билет, я потерял доступ» → показывает код обращения к организатору; ведущий отвязывает билет в админке одной кнопкой.
- Регистрацию можно закрыть в админке. После закрытия новые зрители войти не могут, уже вошедшие продолжают работать. Ведущий закроет её после начала шоу, чтобы никто не набрал себе лишних билетов.
- В админке всегда виден счётчик: сколько билетов зарегистрировано.

## 4. Деньги и голосование
- Каждый зритель при регистрации получает **$1 000 000**.
- Он распределяет их между открытыми проектами как хочет: хоть всё в один, хоть по чуть-чуть.
- **Перекладывать можно в любой момент**, пока голосование открыто. Никаких фаз и раундов.
- Единственная точка остановки: ведущий нажимает **«Закрыть голосование»** в админке. После этого все кнопки у зрителей блокируются, состояние замораживается.

### Управление деньгами в интерфейсе
Никакого ручного ввода сумм - в тёмном зале с телефона это не работает. Только кнопки:
- `+50 000` `+100 000` `+500 000`
- `−50 000` `−100 000` `Забрать всё`

Шаг и набор кнопок вынести в конфиг-файл, чтобы легко поменять перед шоу.

### Серверные правила (проверять только на сервере, клиенту не верить)
- Сумма всех вложений одного зрителя никогда не превышает его бюджет.
- Вложение не может быть отрицательным.
- Любое изменение - **атомарная транзакция**. Клиент присылает «изменить вложение в проект X на дельту D», сервер валидирует и возвращает новое состояние целиком. *(См. D2 — предлагается слать не дельту, а целевую сумму.)*
- Все действия пишутся в лог с меткой времени.
- Если голосование закрыто или проект не открыт - изменение отклоняется.

## 5. Постепенное открытие проектов
Ключевая механика: зритель не должен заранее видеть следующих спикеров.

- В админке заранее заведены все проекты (название, спикер, порядок).
- Каждый проект имеет флаг `is_open`. Изначально все закрыты.
- Ведущий нажимает **«Открыть проект»** перед или после питча - проект появляется у всех зрителей на телефонах в реальном времени.
- Закрытые проекты зрителю **не видны по названию**, но он видит серые заглушки: «Проект №3 - откроется позже». Это важно: иначе первый же зритель сольёт весь миллион в первый проект, не зная, что впереди ещё четыре.
- Открытый проект обратно закрыть можно (на случай ошибки), деньги при этом возвращаются вкладчикам, действие требует подтверждения.

## 6. Что видит зритель (`/app`)
- Крупно сверху: **свободный остаток** из миллиона.
- Список открытых проектов. По каждому: название, спикер, **сколько вложил лично он**, кнопки +/−.
- Ниже - заглушки ещё не открытых проектов.
- **Чужие вложения и общие суммы зрителю не показываются никогда.** Это осознанное решение: если зал видит текущего лидера, все сливают деньги туда же и интрига умирает. Общие цифры живут только на большом экране.
- Сделать это флагом `show_totals_to_guests` в админке (по умолчанию `false`), чтобы можно было передумать на репетиции.
- Индикатор связи: если запрос не прошёл, показать плашку «Нет связи, повторяем...» и повторять автоматически. Не терять действие зрителя.
- После закрытия голосования: экран со своим финальным раскладом и надписью «Голосование закрыто».

## 7. Экран на сцену (`/screen`)
Тёмный фон, огромные цифры, читается с 20 метров. Никакой мелкой типографики.

Режимы переключаются из админки:
1. **QR** - большой QR-код на `/join` + короткая инструкция и счётчик «зарегистрировано: N».
2. **Текущий проект** - название проекта, который сейчас на сцене.
3. **Раскрытие суммы** - сколько денег сейчас у выбранного проекта + сколько зрителей в него вложились. Число выезжает анимацией счётчика, а не появляется мгновенно.
4. **Общий расклад** - горизонтальные полосы по всем открытым проектам с суммами.

Экран обновляется в реальном времени, с агрегацией не чаще раза в секунду. Если связь пропала - показывать последнее известное состояние, а не ошибку. Никогда не показывать на проекторе стектрейс или белый экран.

## 8. Страница итогов (`/screen/results`)
Открывается после закрытия голосования, выводится на проектор.

- Рейтинг всех проектов по сумме, сверху вниз.
- По каждому: сумма, число инвесторов, средний чек.
- Победитель выделен отдельно.
- Кнопка/клавиша для пошагового раскрытия снизу вверх (сначала последнее место, победитель последним) - для драматургии финала.

## 9. Админка (`/admin`)
Доступ по паролю из переменной окружения. Простая форма, сессия в cookie.

**Проекты:** добавить/изменить/удалить, задать порядок, открыть/закрыть, отметить «сейчас на сцене».

**Управление шоу:**
- Регистрация: открыта / закрыта
- Голосование: открыто / закрыто
- Режим экрана: QR / текущий проект / раскрытие суммы / общий расклад
- Выбор проекта для раскрытия

**Зрители:**
- Счётчик зарегистрированных
- Список билетов с их распределением
- Кнопка «отвязать билет» (если человек потерял доступ)
- Режим билетов: `whitelist` / `free`, импорт списка номеров текстом (по одному в строке)

**Мониторинг (на одном экране, обновляется живьём):**
- зарегистрировано зрителей
- распределено денег / осталось нераспределёнными
- суммы по каждому проекту
- время последнего действия

**Опасная зона (с двойным подтверждением):**
- Сбросить все вложения
- Сбросить всё, включая регистрации (для репетиции)

## 10. Схема базы (исходная версия; уточнённая — в ARCHITECTURE.md)
```
show_state (одна строка)
  registration_open      boolean
  voting_open            boolean
  ticket_mode            text     -- 'whitelist' | 'free'
  ticket_format          text
  screen_mode            text     -- 'qr' | 'current' | 'reveal' | 'overview'
  current_project_id     uuid
  reveal_project_id      uuid
  show_totals_to_guests  boolean
  default_budget         bigint   -- 1000000
tickets
  number       text primary key
  claimed_by   uuid null
  claimed_at   timestamptz null
guests
  id           uuid primary key
  token        text unique
  ticket_number text unique
  budget       bigint
  created_at   timestamptz
projects
  id           uuid primary key
  name         text
  speaker      text
  position     int
  is_open      boolean
allocations
  guest_id     uuid
  project_id   uuid
  amount       bigint
  unique (guest_id, project_id)
action_log
  id           bigserial
  guest_id     uuid
  project_id   uuid
  delta        bigint
  created_at   timestamptz
```
Зритель по своему токену видит только свои `allocations` и открытые `projects`. Агрегаты для экрана отдаются отдельным серверным эндпоинтом.

## 11. Порядок работы
Делай по шагам, после каждого шага останавливайся и жди проверки.

1. **База + админка.** Без админки нечего тестировать. На этом шаге - схема, миграции, серверные функции, вход в админку, CRUD проектов, все переключатели.
2. **Вход зрителя.** `/join`, оба режима билетов, токен, обработка занятого билета.
3. **Голосование.** `/app`, кнопки, атомарные транзакции, валидация, оффлайн-очередь.
4. **Экран.** `/screen` со всеми четырьмя режимами, реалтайм, анимация счётчика.
5. **Итоги.** `/screen/results` с пошаговым раскрытием.
6. **Нагрузочный тест.** Скрипт, который поднимает 150 виртуальных зрителей, регистрирует их и в течение двух минут случайно перекладывает деньги. Показывает время отклика и ошибки. Прогнать до репетиции.

## 12. Чек-лист приёмки
- [ ] 150 виртуальных зрителей одновременно двигают деньги, ошибок нет, отклик меньше секунды
- [ ] Сумма вложений зрителя никогда не превышает миллион, даже при быстром спаме кнопок
- [ ] Двойной клик и параллельные вкладки не создают лишних денег
- [ ] Занятый билет не перехватывается вторым устройством
- [ ] После закрытия регистрации новые не входят, старые работают
- [ ] После закрытия голосования никакие изменения не проходят
- [ ] Открытие нового проекта появляется у зрителей быстрее чем за 3 секунды
- [ ] Обрыв связи у зрителя: действие не теряется, восстанавливается само
- [ ] Обрыв связи у экрана: висит последнее состояние, никаких ошибок на проекторе
- [ ] Перезагрузка страницы зрителем: он остаётся собой, деньги на месте
- [ ] Сбросить всё и провести шоу заново - одной кнопкой
- [ ] Экран читается с дальнего ряда
