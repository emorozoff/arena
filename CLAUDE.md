# Арена Единорогов — зрительское голосование виртуальными деньгами

Система для живого шоу: до 800 зрителей (D24; изначально планировали 100–150) с телефонов раскладывают по $1 000 000 между стартапами, результат — на большом экране. Работает один вечер, в зале с плохим интернетом. Ошибаться нельзя.

## С кем работаем
Егор не пишет код и ведёт проект через Claude Code. Поэтому:
- Объясняй по-русски, простыми словами, без жаргона. Если термин неизбежен — расшифруй в скобках один раз.
- В конце каждого шага пиши: **что изменилось** и **как проверить руками** (какую страницу открыть, что нажать, что должно произойти).
- Не делай «магии»: никаких неявных кэшей, хитрых абстракций, генераторов кода. Лучше три понятные строки, чем одна умная.
- Не добавляй зависимости без причины. Каждая новая библиотека — отдельная строчка в ответе: зачем она.
- Имена файлов и функций — говорящие. `allocate.ts`, а не `utils.ts`.

## Приоритеты (в этом порядке)
надёжность → простота управления со сцены → красота экрана → фичи

## Как работаем
1. По этапам из ROADMAP.md. Закончил этап — остановись, опиши, как проверить, жди Егора. Не начинай следующий этап без его «ок».
2. Меняешь архитектуру или спорное поведение — сначала запись в DECISIONS.md, потом код.
3. Меняешь структуру папок, базу или API — обнови ARCHITECTURE.md в том же коммите.
4. Коммить после каждого законченного куска работы, сообщение по-русски: что сделано. Репозиторий: `github.com/emorozoff/arena` (публичный). Прототип на GitHub Pages публикуется **только из ветки `demo`**; `main` — разработка. Обновлять демку (влить `main` в `demo` и запушить) только по команде Егора: её смотрит заказчик.
5. Никогда не запускай сброс базы, деплой или что-либо необратимое без прямой команды Егора в этой сессии.

## Правила кода
- TypeScript везде. Имена переменных и функций — по-английски, комментарии и тексты интерфейса — по-русски.
- Страницы не ходят в сеть сами: только через функции из `web/src/lib/api.ts`. У прототипа тот же набор функций в `api.mock.ts` (D16).
- Все надписи только из `shared/texts.ts`. Все числа-настройки (бюджет, кнопки, формат билета, валюта) только из `shared/config.ts`. В коде страниц ни одной «магической» цифры и ни одной русской строки напрямую.
- Деньги меняются в одном месте на сервере, внутри одной транзакции. Клиент никогда не считает деньги сам.
- Клиенту не верить: сервер проверяет всё заново.
- Никаких таймеров и автоматики по времени: всё в шоу переключает человек кнопкой.
- На проекторе (`/screen`) не может появиться ошибка, стектрейс или белый экран. При обрыве связи — последнее известное состояние.
- Мобильная вёрстка — приоритет для `/join` и `/app`. `/admin` и `/screen` — для ноутбука.

## Запуск
Стек (D1): один Node-сервер (Hono + SQLite + SSE, папка `server/`) и фронт React + Vite + Tailwind (папка `web/`). Общие настройки, тексты и типы — в `shared/`.

```bash
npm install                 # один раз после клонирования
cp .env.example .env        # и вписать ADMIN_PASSWORD (пароль пульта); .env в git не попадает
npm run dev                 # разработка: сервер на порту 3000 + страницы на http://localhost:5173 (телефоны — по адресу Мака из консоли)
npm run check               # проверка типов сервера и фронта — гонять перед каждым коммитом
npm run build && npm start  # как в бою: собрать фронт в dist/ и запустить один сервер, который раздаёт всё сам
npm run dev:demo            # прототип с игрушечным сервером (как на GitHub Pages)
npm run build:pages         # сборка прототипа для GitHub Pages → dist/
npm run build:demo          # прототип одним файлом → demo/arena-demo.html
```

База — файл `data/arena.db` (в git не попадает). Порт занят — сервер напишет об этом по-русски; поменять `PORT` в `.env`.

Прототип для заказчика: https://emorozoff.github.io/arena/ — собирается GitHub Actions из ветки `demo` (`.github/workflows/pages.yml`). Обновление демки: `git checkout demo && git merge main && git push && git checkout main` — только по команде Егора и только из состояния, прошедшего `npm run check` и сборку.

Боевой адрес: https://unicorn-arena.emorozoff.ru (арендованный сервер Егора, D14–D15; настройка на этапе 7).
